## 🧠 1) Distributed Systems & Networking

**1. What is the CAP theorem and how does it apply to distributed systems?**
**Answer:** CAP stands for *Consistency, Availability, Partition tolerance*. In presence of network partitions, a distributed system must choose between consistency and availability. For example, during partition in a database cluster, choosing consistency means rejecting some reads/writes to ensure all nodes agree. Useful when designing systems like distributed queues or service registries.

**2. How do you design a fault-tolerant distributed queue?**
**Answer:** Use replication and persistence (e.g., Kafka, RabbitMQ with mirrored queues). Ensure producers/consumers handle idempotency. Use acknowledgments and retries. Use quorum where applicable to tolerate node failures.

**3. Explain TCP vs UDP and when you’d choose which.**
**Answer:** TCP is connection-oriented with reliability and ordering. UDP is connectionless, faster, no guarantee of delivery. Use TCP for APIs and reliable services; UDP for streaming or high-speed telemetry where occasional loss is acceptable.

**4. How does DNS based service discovery work?**
**Answer:** Services register with DNS names and clients resolve them to IPs. DNS TTL affects freshness; combine with health checks and client-side caching to avoid stale resolutions.

**5. Scenario:** Clients complain of intermittent 500 errors between services. What’s your approach?
**Answer:** Check load balancer logs, service logs, and inter-service latencies. Validate DNS resolution correctness and service discovery TTLs. Use distributed tracing (Jaeger, Zipkin) to pinpoint where latency spikes or timeouts occur.

# 🧠 1) Distributed Systems & Networking (15 Questions + Explained Answers)

### 1. Explain CAP theorem with real-world example.

CAP theorem states that a distributed system can guarantee only two out of three: Consistency, Availability, and Partition Tolerance. During a network partition, the system must choose between serving stale data (availability) or rejecting requests (consistency). For example, in a distributed database like Cassandra, the system may choose availability over strict consistency. In financial systems, consistency is usually preferred.

### 2. What is eventual consistency?

Eventual consistency means that all nodes in a distributed system will eventually converge to the same value if no new updates occur. It allows temporary inconsistency for better availability and performance. This model is common in NoSQL systems like DynamoDB. It works well where immediate consistency is not critical, such as social media feeds.

### 3. What is split-brain problem?

Split-brain happens when nodes in a cluster lose communication and both assume leadership. This causes data corruption or conflicting writes. It commonly occurs during network partitions. Quorum-based voting or consensus algorithms like Raft prevent this by ensuring only majority nodes can make decisions.

### 4. Explain Raft vs Paxos.

Both are consensus algorithms used for distributed coordination. Paxos is mathematically complex and harder to implement. Raft simplifies the process using leader election and log replication in an understandable way. Many modern systems like etcd use Raft because of its clarity and reliability.

### 5. What is backpressure?

Backpressure is a mechanism to control data flow when consumers cannot keep up with producers. It prevents system overload and memory exhaustion. For example, Kafka slows producers if consumers lag significantly. TCP also uses flow control to manage backpressure.

### 6. L4 vs L7 load balancing?

Layer 4 load balancing operates at the transport layer using IP and port. It is faster and simpler. Layer 7 operates at application layer, routing based on URL, headers, or cookies. L7 enables smarter routing like path-based traffic splitting.

### 7. Explain DNS-based service discovery.

Services register DNS names that clients resolve into IP addresses. DNS caching and TTL impact how quickly updates propagate. It is simple but less dynamic compared to service mesh solutions. Failures are handled via health checks and TTL expiry.

### 8. What is a circuit breaker?

A circuit breaker prevents repeated calls to a failing service. After detecting failures, it opens the circuit and blocks calls temporarily. Once healthy, it allows limited test traffic. This prevents cascading failures across microservices.

### 9. How to debug intermittent latency spikes?

Start by checking network metrics and service logs. Use distributed tracing to see slow service hops. Inspect thread pools, GC pauses, and retry storms. Identify whether latency is internal or from upstream dependency.

### 10. What is idempotency in APIs?

An idempotent operation produces the same result when executed multiple times. For example, PUT requests are idempotent. It is important in distributed systems to safely retry failed requests. Payment systems often use idempotency keys.

### 11. What are distributed locks?

Distributed locks coordinate access across nodes. They ensure only one node performs a critical operation. Tools like Redis Redlock or Zookeeper are commonly used. Improper implementation may lead to deadlocks.

### 12. What is gossip protocol?

Gossip protocol spreads information randomly among nodes. It ensures cluster state propagation in scalable systems. Used in Cassandra and Consul. It is fault tolerant and decentralized.

### 13. What is thundering herd problem?

It occurs when many clients retry simultaneously after a failure. This overwhelms the system again. Exponential backoff with jitter helps prevent it. Circuit breakers also reduce impact.

### 14. Explain TCP three-way handshake.

TCP establishes connection using SYN → SYN-ACK → ACK. This ensures both sides agree on communication. It initializes sequence numbers and ensures reliability before data transfer.

### 15. How to design highly available distributed queue?

Use replication across nodes with leader election. Persist messages to disk for durability. Use acknowledgments to ensure safe processing. Implement partitioning for scalability.

# 🐧 3) Linux & OS Fundamentals (15 Questions + Explained Answers)

### 1. What happens when you execute a command in Linux?

When you execute a command, the shell parses it and creates a new process using `fork()`. The new process replaces itself with the target program using `exec()`. The kernel scheduler assigns CPU time. The process runs in user mode but may switch to kernel mode for system calls. After completion, it returns an exit status.

### 2. Explain load average.

Load average represents the number of processes waiting for CPU or I/O over 1, 5, and 15 minutes. A load equal to CPU cores means full utilization. Higher values indicate CPU contention. It includes both running and runnable processes.

### 3. Soft link vs Hard link?

A hard link points directly to the inode of a file, meaning both filenames share the same data. A soft link (symbolic link) is a pointer to the file path. Deleting the original file breaks a soft link but not a hard link. Hard links cannot span filesystems.

### 4. What is a zombie process?

A zombie process has completed execution but still has an entry in the process table. It occurs when the parent does not call `wait()`. Zombies consume minimal resources but may indicate improper process handling.

### 5. How do you debug high I/O wait?

Use `iostat`, `vmstat`, and `iotop` to identify disk bottlenecks. Check if swap usage is high. Look for processes performing heavy read/write operations. Disk saturation or slow storage often causes high I/O wait.

### 6. What are cgroups?

Control groups (cgroups) limit CPU, memory, and I/O usage of processes. Containers rely on cgroups for isolation. They prevent a single process from exhausting system resources.

### 7. What is systemd?

Systemd is the init system that manages services and boot processes. It handles dependency management and parallel startup. Services are controlled using `systemctl`.

### 8. How to check open ports?

Use `ss -lntp` or `netstat -tulnp` to list listening ports and associated processes. This helps diagnose unexpected services running.

### 9. Impact of swap usage?

Swap moves memory pages to disk when RAM is full. Heavy swapping degrades performance significantly. It indicates memory pressure.

### 10. How to detect memory leak?

Monitor process RSS growth using `top` or `ps`. Check heap usage using profilers. Gradual increase without release indicates leak.

### 11. What is strace?

Strace traces system calls made by a process. It helps debug permission issues, file access errors, and unexpected behavior.

### 12. What are file descriptors?

File descriptors are handles for open files, sockets, and pipes. Each process has limits (`ulimit -n`). Exhausting them causes “too many open files” errors.

### 13. How to secure SSH?

Disable root login, enforce key-based authentication, change default port, and use fail2ban to prevent brute force.

### 14. How does cron work?

Cron is a time-based scheduler that executes tasks defined in crontab. It runs as a daemon checking schedule entries every minute.

### 15. Server CPU at 100% – steps?

Identify top process using `top`. Check threads and logs. Determine if issue is compute-heavy or stuck loop. Restart only if root cause understood.

## 1️⃣ Disk Usage Alert Script

### ✅ Problem

Write a script that alerts if disk usage exceeds 80%.

### 💡 Answer

```bash
#!/bin/bash

THRESHOLD=80

df -h | awk 'NR>1 {print $5 " " $1}' | while read output;
do
  usage=$(echo $output | awk '{print $1}' | sed 's/%//g')
  partition=$(echo $output | awk '{print $2}')

  if [ $usage -ge $THRESHOLD ]; then
    echo "ALERT: $partition usage is at ${usage}%"
  fi
done
```

✔ Parses `df -h`
✔ Removes `%`
✔ Compares threshold
✔ Production-ready logic

## 6️⃣ Log Analyzer – Top 3 Errors

### ✅ Problem

Find top 3 most frequent ERROR messages.

### 💡 Answer

```python
from collections import Counter

errors = []

with open("app.log") as f:
    for line in f:
        if "ERROR" in line:
            errors.append(line.strip())

counter = Counter(errors)

for error, count in counter.most_common(3):
    print(error, count)
```

✔ Efficient frequency counting
✔ Works for large logs

## 7️⃣ Retry with Exponential Backoff

### ✅ Problem

Retry API up to 5 times with exponential delay.

### 💡 Answer

```python
import requests
import time

url = "https://example.com"

for attempt in range(5):
    try:
        response = requests.get(url, timeout=5)
        if response.status_code == 200:
            print("Success")
            break
    except:
        pass

    sleep_time = 2 ** attempt
    print(f"Retrying in {sleep_time} seconds...")
    time.sleep(sleep_time)
```

✔ Implements resilience
✔ Prevents thundering herd

## 8️⃣ Simple Round Robin Load Balancer

### ✅ Problem

Return next backend server each call.

### 💡 Answer

```python
class LoadBalancer:
    def __init__(self, servers):
        self.servers = servers
        self.index = 0

    def get_server(self):
        server = self.servers[self.index]
        self.index = (self.index + 1) % len(self.servers)
        return server

lb = LoadBalancer(["10.0.0.1", "10.0.0.2", "10.0.0.3"])

print(lb.get_server())
print(lb.get_server())
```

✔ Cyclic index

## 9️⃣ Token Bucket Rate Limiter

### ✅ Problem

Implement simple rate limiter.

### 💡 Answer

```python
import time

class TokenBucket:
    def __init__(self, rate, capacity):
        self.rate = rate
        self.capacity = capacity
        self.tokens = capacity
        self.last_refill = time.time()

    def allow_request(self):
        now = time.time()
        elapsed = now - self.last_refill
        self.tokens = min(self.capacity, self.tokens + elapsed * self.rate)
        self.last_refill = now

        if self.tokens >= 1:
            self.tokens -= 1
            return True
        return False

bucket = TokenBucket(rate=1, capacity=5)
print(bucket.allow_request())
```

✔ Used in API gateways
✔ Implements refill logic

## 🔟 Circuit Breaker Implementation

### ✅ Problem

Stop calling service after 3 failures.

### 💡 Answer

```python
class CircuitBreaker:
    def __init__(self, failure_threshold):
        self.failure_threshold = failure_threshold
        self.failure_count = 0
        self.state = "CLOSED"

    def call(self, func):
        if self.state == "OPEN":
            print("Circuit Open")
            return

        try:
            func()
            self.failure_count = 0
        except:
            self.failure_count += 1
            if self.failure_count >= self.failure_threshold:
                self.state = "OPEN"

def test():
    raise Exception("Fail")

cb = CircuitBreaker(3)
for _ in range(5):
    cb.call(test)
```

✔ Implements failure tracking
✔ Basic resilience pattern

import requests

urls = ["https://google.com", "https://example.com"]

    try:
        r = requests.get(url, timeout=3)
